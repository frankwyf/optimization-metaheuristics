# 1.3.0 — Reproducible optimization experiments

This release turns the four bounded minimizers into a reusable library with a
shared experiment runner, while keeping the canonical welded-beam objective,
constraints, and reference optimum intact. The project remains a research and
education library; no global convergence or engineering certification is claimed.

## Features

- Use `OptimizationProblem` for custom bounded objectives and `g(x) <= 0` constraints.
- Run explicit seed plans through `metaheuristics.experiments.run_experiment`.
- Export schema v2 JSON and CSV with actual seeds, full histories, feasibility,
  evaluation counts, effective algorithm settings, and environment versions.
- Use `metaheuristics-run` or `python -m metaheuristics`. Plotting is optional.

## Correctness fixes and migration

- PSO and GA use instance-local random generators; global RNG state is preserved.
- SA returns the best evaluated candidate even after accepting a worse state.
  Its acceptance rule still uses the current state and Boltzmann probability.
- GA includes improvements produced by the final generation in its result.
- GA and SA histories now include the initial state followed by completed updates,
  consistent with PSO and DE. Default histories record best penalized values.
- Invalid counts, temperatures, rates, seeds, and non-finite bounds/penalties fail
  with a clear error. DE retains its legacy clamp of positive populations 1–3 to 4.
- Unsupported CLI options now fail instead of silently being ignored.
- If `--seed` is omitted, actual generated seeds are printed and exported.
  Schema v1 consumers should accept schema v2 and its added `seeds`/`std_ddof` fields.
- `best_cost` retains its legacy feasible/raw versus infeasible/penalized meaning;
  new code should read `objective_value`, `penalized_cost`, and `is_feasible` explicitly.

Seed sequences and result histories can change because of the correctness fixes.
Exact replay is scoped to deterministic callbacks and the same package and
dependency versions. Timing values are measurements and are not deterministic.
Custom callback source is not serialized. See [API.md](../API.md) and
[EXPERIMENTS.md](../EXPERIMENTS.md) for replay and comparison guidance.

The [validation report](1.3.0-validation.md) includes all 320 paired before/after
runs, settings, feasibility, objective statistics, timings, and convergence diagnostics.

## Packaging and release checks

The package version has one source, citation metadata is synchronized, and CI
tests installed wheels. Tagged releases must match the version, point to a
commit contained in `master`, pass the full CI workflow again, and pass distribution
metadata checks. GitHub assets include the wheel, source archive, and SHA-256 sums.
PyPI publishing uses OIDC and requires the configured `pypi` environment and
Trusted Publisher; it cannot be inferred from a successful GitHub Release.
